连接重试上限与恢复阶段的证据台账

GitHub 十月复盘给出同步重连放大负载及随后限制连接、随机延迟的实例，为小型服务的重试验收提供公开依据；这不诊断任何本地客户端，也不证明特定方案已在所有环境有效。

阅读原文 · GitHub · 重连随机延迟改进 ↗
适合谁
维护 API 客户端、定时任务与队列的小团队及开发者。
第一步
用自编状态序列在纸面模拟连接失败、限流和恢复，分别列并发上限、最大重试、退避、任务幂等与积压清空证据，不向真实服务制造故障或负载。
窗口
未来一周先做虚构状态回放与维护清单，无申请截止或收益保证。
风险与不确定性
退避参数和故障范围依赖系统；连接成功不代表任务完成，切换区域也可能转移过载；样例不能替代生产监测或独立容量验证。
