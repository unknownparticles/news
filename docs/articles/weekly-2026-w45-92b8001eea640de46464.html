GitHub 指南把代理工程拆为计划、实现、验证与观察

GitHub 发布代理工程实践指南，将软件工作划分为 Plan、Build、Verify、Observe，讨论明确需求、验收标准、项目上下文、审查及生产反馈。它是厂商工作流建议，所引调查和产品示例未由本期独立复核，不把自动起草代码或 PR 视为完成质量与收益证明。各计划的功能和费用仍需分别确认。

为什么值得关注

代码生成加速可能把压力转移到审查和验收，实际完成工作需看缺陷、返工和运行证据。

下一步

用虚构小工单定义输入、测试、审查与观察指标，比较完成率与总耗时，不新授权仓库或自动合并。
